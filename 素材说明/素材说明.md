# 绘本素材命名与网页视频说明

依据：《小傩面找身份_修订版分页脚本(2).pdf》。采用这次上传脚本中的顺序：太婆→将军→秦童→先锋小姐。本次只整理素材，不改写用户脚本。

## 文件夹

- `原图/`：37 张原图，只重命名，内容不变。
- `对应视频/`：36 个原视频，只重命名，原 HEVC/AAC 内容不变。
- `网页视频/`：36 个网页兼容副本，MP4 / H.264 Baseline / yuv420p / AAC，保留尺寸、声音和时长，启用 faststart。
- `素材说明/素材命名对照表.csv`：可以用 Excel 打开，记录原文件名、新文件名、场景和 SHA-256。
- `素材说明/素材命名对照表.json`：同一份可逆命名记录，供后续程序使用。
- `素材说明/网页视频验证报告.json`：当前转换结果的参数、全片解码检查结果。

## 仍需处理的对应关系

1. 作者已确认第12页使用桥边笑脸特写，改名为 `page-12-pattern-growth`；正文与热点随之调整，不再描述小动物围绕、河边倒影。
2. 脚本第21页引用第二十页旧图名，但新素材已有三种山顶展示图，因此按实际画面命名为 `page-21-A/B/C-...`。
3. 脚本第22页写“需新绘”，现在已有三种老爷爷在工坊手持面具的图与视频；其画面对应变回面具后的状态，不把静态终态当作已经完整实现的变身动画。
4. A蓝白结尾对应蓝白舞台画面；不沿用脚本第25A页里错写的旧编号（1）。
5. 第02页素材展示工坊人形；是否呈现了脚本描述的完整变身过程，还需按实际视频动作检查和设计衔接。
6. 第26页是另一幅工坊构图；脚本要求的可点击空位需在交互设计时定位，不能直接沿用开场热点坐标。
7. `page-20-mask-options-reference.jpg` 是三面具合图，不是三张单独的透明按钮素材。

## 重新转换的方法

已提供可重复运行的脚本，需 Python 3、FFmpeg（含 libx264）和 ffprobe：

```bash
python "素材说明/转换网页视频.py"
```

脚本会读取仓库内 `对应视频/`，写入 `网页视频/`；不改原视频。已有兼容版会重新验证后跳过。若改变原视频内容，应先将对应网页副本移到备份目录，再运行以生成新版。

单个视频的等价命令：

```bash
ffmpeg -i "输入.mp4" -map 0:v:0 -map "0:a:0?" -c:v libx264 -preset medium -crf 20 -profile:v baseline -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart "输出-web.mp4"
```

仅改扩展名、选择MP4容器、或使用 `-c copy` 都不会将HEVC转换为H.264。

### 不用命令行：HandBrake

1. 从 HandBrake 官网 https://handbrake.fr/ 安装并打开软件，选择原视频。
2. 预设可选 `Fast 720p30`；确认输出格式为 `MP4`，勾选 `Web Optimized`（网络优化）。
3. 视频编码选择 `H.264 (x264)`，帧率选择与源相同（这些源视频为720p；如预设限帧则不超过30fps），质量 RF 可设20–22。
4. 音频编码选择 `AAC`，码率128 kbps。
5. 输出到新文件夹，加入队列后开始编码；不要覆盖原视频。

## 验证范围

命名前后对73份原素材核对SHA-256。兼容版检查H.264、yuv420p、AAC、尺寸与音轨数、时长差小于0.15秒、moov在mdat之前，并逐片完整解码。转码属于有损编码，内容未剪辑，但不宣称像素完全一致。

这些检查不等于在真实手机、Safari、Chrome和微信内逐一测试，也不等于检查了全部动画的美术连贯性。后续网页接入使用 `网页视频/`，并配置封面图、播放按钮、`playsinline`；是否自动播放还受浏览器声音策略限制。
